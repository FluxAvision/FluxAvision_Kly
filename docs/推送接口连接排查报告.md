## ❌ 根因分析

### 根因：设备配置的目标 IP 地址错误

| 项目 | 值 |
|------|-----|
| **本服务器实际 IP** | **`192.168.1.2`** |
| **设备配置的目标 IP** | **`192.168.1.102`** |
| 192.168.1.102 是否存在 | ❌ **不存在**（ping 超时，ARP 表中无该 IP） |

**问题描述：**
双目客流相机配置的推送目标地址为 `http://192.168.1.102:15678/...`，但当前服务器实际的 IP 地址是 `192.168.1.2`（已通过 `ipconfig` 确认）。`192.168.1.102` 不在本机地址中，也无法从 ARP 表中找到对应设备。

**可能的原因：**
1. 服务器 IP 被路由器 DHCP 重新分配（原先可能是 192.168.1.102，现在变为 192.168.1.2）
2. 配置设备时填错了目标 IP 地址
3. 多网卡环境下设备指向了错误网口

---

## 修复方案

### 方案一（推荐）：修改设备的推送目标 IP

在相机/设备管理后台，将推送目标地址从：

```
http://192.168.1.102:15678/klyun/kl/equipapi/binocular/dataUpload
```

改为：

```
http://192.168.1.2:15678/klyun/kl/equipapi/binocular/dataUpload
```

**同时需修改心跳地址：**
```
http://192.168.1.2:15678/klyun/kl/equipapi/binocular/heartBeat
```

---

### 方案二：给服务器配置静态 IP（可选）

为了避免下次 DHCP 重新分配 IP 导致再次断连，建议给服务器设置**静态 IP**：

1. 打开 **控制面板 → 网络和 Internet → 网络连接**
2. 右键"以太网" → **属性**
3. 双击 **"Internet 协议版本 4 (TCP/IPv4)"**
4. 选择 **"使用下面的 IP 地址"**
5. 填写：
   - IP 地址：`192.168.1.2`
   - 子网掩码：`255.255.255.0`
   - 默认网关：`192.168.1.1`
   - DNS：`192.168.1.1`（或 `114.114.114.114`）

---

### 方案三：添加防火墙入站规则（保障用）

Windows 防火墙当前为**公用网络**配置文件，采用 **BlockInbound** 策略。虽然没有明确阻止 15678 端口，但为了确保局域网其他设备能访问，建议添加显式放行规则：

```batch
netsh advfirewall firewall add rule name="FluxAvision API 15678" dir=in action=allow protocol=TCP localport=15678
```

> 如果防火墙没有阻止访问，此步骤不是必须的，但添加规则无害。

## 结论

**根本原因：** 设备配置的推送目标 IP 为 `192.168.1.102`，但服务器的实际 IP 为 `192.168.1.2`。`192.168.1.102` 无设备响应。

**最快修复：** 将设备的推送目标 IP 从 `192.168.1.102` 改为 `192.168.1.2`，同时建议给服务器配置静态 IP。

**次要建议：** 添加防火墙入站规则放行 TCP 15678 端口，确保网络策略不会影响通信。
