## 1. 前置条件

在开始集成之前，请确保满足以下条件。

### 1.1 系统版本要求

| 项目 | 要求 |
|------|------|
| 客流芸系统版本 | v2.0.0 及以上 |
| 第三方设备 | 支持 HTTP POST 推送的客流相机或系统（如 KLY 系列双目客流相机） |

### 1.2 权限要求

- 您需要拥有客流芸系统的**设备管理**操作权限
- 系统**不需要** Token / API Key / JWT 认证即可接收设备推送数据
- 设备推送接口对外直接可用，**无额外认证**（建议在内网或 VPN 环境部署）

### 1.3 网络要求

| 项目 | 说明 |
|------|------|
| 客流芸服务器 IP | 请向系统管理员获取（如 `192.168.1.100`） |
| 端口（默认） | **15678**（TCP） |
| 协议 | **HTTP**（设备到服务器的推送） |
| 网络连通性 | 相机设备须能**访问**客流芸服务器的 IP 和端口 |
| 防火墙 | 需放行 TCP 端口 15678，允许设备 IP 访问 |

> ⚠️ **注意**：默认端口可通过系统环境变量 `API_PORT` 修改，请以实际部署端口为准。  
> ⚠️ **安全建议**：如需公网暴露，请在反向代理层（如 Nginx）添加 IP 白名单或 HTTP Basic Auth。

## 2. 推送接口详解

客流芸系统支持两个推送接口：

| 接口 | 用途 | 推送频率 |
|------|------|---------|
| **心跳上传** | 监测设备在线状态 | 设备上电后**每分钟一次** |
| **数据上传** | 推送客流进出计数 | 有人经过时触发（实时模式）或按固定间隔上报 |

两个接口的响应格式相同，均返回 `code: 0` 表示成功，`code: 1` 表示失败。

---

### 2.1 心跳上传接口

> 用于监测设备是否在线。设备上电后每分钟自动上报一次。

#### 2.1.1 接口信息

| 项目 | 值 |
|------|------|
| **URL** | `http://<服务器IP>:15678/klyun/kl/equipapi/binocular/heartBeat` |
| **Method** | `POST` |
| **Content-Type** | `application/json` |
| **认证方式** | 无（直接 IP + 端口推送） |

#### 2.1.2 请求体 JSON 格式

```json
{
  "version": 1,
  "macAddress": "4C:BC:98:60:10:8E",
  "ipAddress": "192.168.8.210",
  "connectionType": "Wired",
  "ipAddressMethod": "DHCP",
  "hostName": "Cam-13889",
  "timeZone": 8,
  "hwPlatform": "V3.0",
  "swRelease": "V6.3.6",
  "reportDate": "2023-04-17",
  "sn": "2010012104250097",
  "time": 1631947237
}
```

#### 2.1.3 请求体字段说明

| 字段 | 类型 | 必填 | 说明 | 示例值 |
|------|------|------|------|--------|
| `sn` | string | **是** | 设备序列号，用于匹配系统中注册的设备 | `"2010012104250097"` |
| `version` | int | 否 | 接口版本 | `1` |
| `macAddress` | string | 否 | 设备 MAC 地址 | `"4C:BC:98:60:10:8E"` |
| `ipAddress` | string | 否 | 设备 IP 地址（系统会根据此字段更新设备的 IP） | `"192.168.8.210"` |
| `connectionType` | string | 否 | 网络连接方式：`Wired`（有线）或 `Wireless`（无线） | `"Wired"` |
| `ipAddressMethod` | string | 否 | IP 获取方式：`DHCP` 或 `STATIC` | `"DHCP"` |
| `hostName` | string | 否 | 设备主机名（若设备尚未命名，系统会用此值填充设备名称） | `"Cam-13889"` |
| `timeZone` | int | 否 | 时区偏移，如 `8` 表示 UTC+8 | `8` |
| `hwPlatform` | string | 否 | 硬件平台版本 | `"V3.0"` |
| `swRelease` | string | 否 | 固件版本 | `"V6.3.6"` |
| `reportDate` | string | 否 | 上报日期（格式 `YYYY-MM-DD`） | `"2023-04-17"` |
| `time` | int | 否 | Unix 时间戳（秒），设备端当前时间 | `1631947237` |

#### 2.1.4 响应格式

**成功响应（HTTP 200）：**

```json
{
  "code": 0,
  "msg": "success",
  "data": {
    "sn": "2010012104250097",
    "time": 1680000000
  }
}
```

**失败响应（HTTP 200，但 code ≠ 0）：**

```json
{
  "code": 1,
  "msg": "device not registered",
  "data": {}
}
```

#### 2.1.5 响应字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| `code` | int | 状态码：`0` = 成功，`1` = 失败 |
| `msg` | string | 状态信息：成功为 `"success"`，失败时描述错误原因 |
| `data.sn` | string | 设备序列号（原样返回） |
| `data.time` | int | 服务器的 Unix 时间戳（秒），设备**可用此值同步设备端时间** |

> 💡 **提示**：`data.time` 是服务器返回的当前时间戳。双目客流相机收到后会用它校准设备时间。

#### 2.1.6 处理逻辑（供参考）

```
接收到心跳请求
  → 解析 JSON 提取 sn
  → 在数据库中根据 serialNumber 查找设备
    ├─ 找到 → 更新设备状态为 online，更新 IP 地址
    └─ 未找到 → 返回 code: 1, msg: "device not registered"
```

### 2.2 数据上传接口

> 当有顾客进出时，设备向此接口推送客流计数数据。

#### 2.2.1 接口信息

| 项目 | 值 |
|------|------|
| **URL** | `http://<服务器IP>:15678/klyun/kl/equipapi/binocular/dataUpload` |
| **Method** | `POST` |
| **Content-Type** | `application/json` |
| **认证方式** | 无（直接 IP + 端口推送） |

#### 2.2.2 请求体 JSON 格式

```json
{
  "version": 1,
  "macAddress": "4C:BC:98:60:10:8E",
  "ipAddress": "192.168.8.210",
  "connectionType": "Wired",
  "ipAddressMethod": "DHCP",
  "hostName": "Cam-13889",
  "timeZone": 8,
  "hwPlatform": "V3.0",
  "swRelease": "V6.3.6",
  "reportDate": "2023-04-17",
  "sn": "2010012104250097",
  "time": 1631947237,
  "startTime": 1612319472237,
  "endTime": 1612319477237,
  "in": 1,
  "out": 2,
  "passby": 2,
  "turnback": 3,
  "avgStayTime": 2000
}
```

#### 2.2.3 请求体字段说明

| 字段 | 类型 | 必填 | 说明 | 示例值 |
|------|------|------|------|--------|
| `sn` | string | **是** | **设备序列号**，用于匹配系统中注册的设备 | `"2010012104250097"` |
| `endTime` | int | **是** | 数据结束时间，**Unix 毫秒时间戳（13位）**。系统据此确定数据归属的日期和小时 | `1612319477237` |
| `version` | int | 否 | 接口版本 | `1` |
| `macAddress` | string | 否 | 设备 MAC 地址 | `"4C:BC:98:60:10:8E"` |
| `ipAddress` | string | 否 | 设备 IP 地址 | `"192.168.8.210"` |
| `connectionType` | string | 否 | 连接方式：`Wired` / `Wireless` | `"Wired"` |
| `ipAddressMethod` | string | 否 | IP 获取方式：`DHCP` / `STATIC` | `"DHCP"` |
| `hostName` | string | 否 | 设备主机名 | `"Cam-13889"` |
| `timeZone` | int | 否 | 时区偏移 | `8` |
| `hwPlatform` | string | 否 | 硬件平台版本 | `"V3.0"` |
| `swRelease` | string | 否 | 固件版本 | `"V6.3.6"` |
| `reportDate` | string | 否 | 上报日期 | `"2023-04-17"` |
| `time` | int | 否 | 当前数据的最新 Unix 时间戳（秒） | `1631947237` |
| `startTime` | int | 否 | 数据起始时间，Unix **毫秒**时间戳（13位） | `1612319472237` |
| `in` | int | 否 | **该时段内进入人数**，默认为 0 | `1` |
| `out` | int | 否 | **该时段内离开人数**，默认为 0 | `2` |
| `passby` | int | 否 | 该时段内经过人数（仅从门口经过不进入），默认为 0 | `2` |
| `turnback` | int | 否 | 该时段内折返人数（到了门口又折返），默认为 0 | `3` |
| `avgStayTime` | int | 否 | 平均逗留时间，单位：**毫秒** | `2000` |

> ⚠️ **关于时间戳**：`startTime` 和 `endTime` 支持两种格式自动兼容：
> - **13 位数字** → 按**毫秒**处理（推荐，精度更高）
> - **10 位数字** → 按**秒**处理（向下兼容）
>
> 系统根据 `endTime` 计算出日期（`YYYY-MM-DD`）和小时（`0-23`），然后按此维度累加客流数据。

#### 2.2.4 响应格式

**成功响应（HTTP 200）：**

```json
{
  "code": 0,
  "msg": "success",
  "data": {
    "sn": "2010012104250097",
    "time": 1680000000
  }
}
```

**失败响应（HTTP 200，但 code ≠ 0）：**

```json
{
  "code": 1,
  "msg": "device not registered",
  "data": {}
}
```

#### 2.2.5 处理逻辑（供参考）

```
接收到数据推送
  → 解析 JSON 提取 sn、endTime、in、out 等字段
  → 根据 serialNumber 查找设备
    ├─ 未找到 → 返回 code: 1, msg: "device not registered"
    └─ 找到设备 →
        → 根据 endTime 计算 date (YYYY-MM-DD) 和 hour (0-23)
        → 查找该设备 + date + hour 的客流记录
          ├─ 不存在 → 创建新记录
          └─ 存在 → 累加到已有记录
        → countIn += in
        → countOut += out
        → passby += passby
        → turnback += turnback
        → avgStayTime = 最新值（覆盖）
        → 更新设备状态为 online
```

> 💡 **数据累加规则**：同一天同一小时内多次推送的数据会**累加**而非覆盖。例如，14:05 推送 `in: 1`、14:08 又推送 `in: 2`，则该小时最终 `countIn = 1 + 2 = 3`。

## 3. 配置步骤（从 0 到 1）

### 步骤 1：在客流芸系统中添加设备

> 设备推送前，必须先将其序列号（SN）注册到客流芸系统中。否则所有推送都会被拒绝（返回 `code: 1`）。

**方式 A：通过 Web 界面添加（推荐）**

1. 打开客流芸 Web 管理界面（在浏览器访问 `http://<服务器IP>:15678`）
2. 进入 **「设备管理」** 页面
3. 点击 **「添加设备」** 按钮
4. 填写以下信息：

   | 字段 | 说明 | 示例 |
   |------|------|------|
   | **设备名称** | 为设备起一个好记的名字 | `"正门入口"` |
   | **序列号 (SN)** | **与相机设备端 SN 保持一致** | `"2010012104250097"` |
   | **IP 地址** | 设备的 IP 地址（可选，心跳后会自动更新） | `"192.168.1.101"` |
   | **安装位置** | 设备安装在什么地方 | `"一楼正门"` |
   | **设备型号** | 可选择 `"KLY系列"` 或其他 | `"KLY系列"` |

5. 点击 **「保存」**，设备即添加完成

**方式 B：通过 API 添加（适用于批量添加）**

```bash
curl -X POST http://<服务器IP>:15678/api/devices \
  -H "Content-Type: application/json" \
  -d '{
    "name": "正门入口",
    "serialNumber": "2010012104250097",
    "ip": "192.168.1.101",
    "location": "一楼正门",
    "model": "KLY系列"
  }'
```

**确认添加成功：**

```bash
curl http://<服务器IP>:15678/api/devices
```

返回的设备列表中应能看到刚刚添加的设备。

### 步骤 2：配置第三方设备指向推送地址

在双目客流相机（或第三方设备/系统）的配置界面中，设置以下参数：

| 配置项 | 值 | 说明 |
|--------|------|------|
| **服务器地址** | 客流芸系统的 IP 或域名 | 如 `192.168.1.100` |
| **端口** | `15678` | 客流芸系统默认端口 |
| **推送路径（数据上传）** | `/klyun/kl/equipapi/binocular/dataUpload` | 固定路径 |
| **推送路径（心跳）** | `/klyun/kl/equipapi/binocular/heartBeat` | 固定路径 |
| **上传间隔** | `0`（实时上报）或大于 0 的整数（秒） | `0` 表示有人经过立即触发上报 |
| **设备 SN** | 与系统中注册的 serialNumber 一致 | 如 `"2010012104250097"` |

> 💡 **在 KLY 相机上的操作示意**：
> 1. 登录相机管理界面
> 2. 找到 **「服务器设置」** 或 **「推送设置」**
> 3. 启用推送功能，填写上述参数
> 4. 点击 **「保存/应用」**

**如果第三方设备不支持配置路径，仅支持配置完整 URL：**

```
数据上传 URL: http://192.168.1.100:15678/klyun/kl/equipapi/binocular/dataUpload
心跳 URL:     http://192.168.1.100:15678/klyun/kl/equipapi/binocular/heartBeat
```

### 步骤 3：验证推送是否成功

#### 3.1 检查心跳

设备上电后约 1 分钟内，应能收到心跳请求。可通过系统界面检查设备状态：

1. 打开客流芸 Web 界面 → **「设备管理」**
2. 查看设备状态是否变为 **"在线"**
3. 设备状态显示 **"在线"** 表示心跳推送成功

#### 3.2 检查数据

设备前方有人经过后：

1. 打开客流芸 Web 界面 → **「仪表盘」**
2. 查看对应设备的今日客流数据是否增加
3. 或访问客流数据 API：

```bash
curl "http://<服务器IP>:15678/api/traffic/history?deviceId=<设备ID>&startDate=2026-05-28&endDate=2026-05-28&dimension=hourly"
```

### 步骤 4：排查常见问题

如果设备推送后系统没有反应，请按以下顺序排查：

**检查清单：**

1. ☐ 设备 SN 是否已在系统中注册？（请确认 `serialNumber` 与推送的 `sn` **完全一致**，注意大小写和前后空格）
2. ☐ 网络是否通畅？（从设备端 ping 服务器 IP，telnet 端口 15678）
3. ☐ 防火墙是否放行了端口 15678？
4. ☐ 推送地址是否正确？（检查 URL 拼写和端口号）
5. ☐ 推送的 JSON 格式是否正确？（可使用下面的 curl 测试）

> 📮 如果以上检查均无问题但推送仍失败，请查看系统的**推送日志**（参见第 5 节）。

```bash
echo ""

curl -X POST http://${SERVER_IP}:${PORT}/klyun/kl/equipapi/binocular/dataUpload \
  -H "Content-Type: application/json" \
  -d "{
    \"sn\": \"${DEVICE_SN}\",
    \"endTime\": $(date +%s)000,
    \"in\": 1,
    \"out\": 2,
    \"passby\": 2,
    \"turnback\": 3,
    \"avgStayTime\": 2000

echo ""
echo "=== 步骤3：查询推送后的客流数据 ==="
TODAY=$(date +%Y-%m-%d)
curl "http://${SERVER_IP}:${PORT}/api/traffic/history?deviceId=$(curl -s http://${SERVER_IP}:${PORT}/api/devices | python -c \"import sys,json; devices=json.load(sys.stdin)['data']; print(next(d['id'] for d in devices if d['serialNumber']=='${DEVICE_SN}'))\" 2>/dev/null)&startDate=${TODAY}&endDate=${TODAY}&dimension=hourly" | python -m json.tool
```

### 4.2 Python 示例代码

以下是一个完整的 Python 实现，涵盖心跳和客流数据推送：

```python
#!/usr/bin/env python3
"""
客流芸系统 - 设备推送接入示例

使用说明：
  1. 修改 SERVER_HOST 和 DEVICE_SN 为实际值
  2. 确保设备已在客流芸系统中注册（serialNumber = DEVICE_SN）
  3. 运行脚本

依赖：
  pip install requests
"""

import time
import requests
import json

# ==================== 配置 ====================
SERVER_HOST = "192.168.1.100"   # 客流芸服务器 IP
SERVER_PORT = 15678              # 客流芸服务器端口
DEVICE_SN = "2010012104250097"   # 设备序列号（须与系统注册的 serialNumber 一致）

# ==================== 接口地址 ====================
BASE_URL = f"http://{SERVER_HOST}:{SERVER_PORT}"
HEARTBEAT_URL = f"{BASE_URL}/klyun/kl/equipapi/binocular/heartBeat"
DATA_UPLOAD_URL = f"{BASE_URL}/klyun/kl/equipapi/binocular/dataUpload"
DEVICE_LIST_URL = f"{BASE_URL}/api/devices"

HEADERS = {"Content-Type": "application/json"}


def push_heartbeat() -> dict:
    """
    推送心跳数据（应在设备运行期间每分钟调用一次）。
    
    返回服务器响应字典。
    """
    payload = {
        "version": 1,
        "macAddress": "4C:BC:98:60:10:8E",
        "ipAddress": "192.168.8.210",
        "connectionType": "Wired",
        "hostName": f"Cam-{DEVICE_SN[-5:]}",
        "timeZone": 8,
        "hwPlatform": "V3.0",
        "swRelease": "V6.3.6",
        "sn": DEVICE_SN,
        "time": int(time.time()),
    }

    try:
        resp = requests.post(HEARTBEAT_URL, json=payload, headers=HEADERS, timeout=10)
        result = resp.json()
        if result.get("code") == 0:
            print(f"[✓] 心跳推送成功 | sn={DEVICE_SN}")
        else:
            print(f"[✗] 心跳推送失败 | code={result.get('code')} msg={result.get('msg')}")
        return result
    except requests.exceptions.RequestException as e:
        print(f"[✗] 心跳推送异常 | {e}")
        return {"code": -1, "msg": str(e)}


def push_traffic_data(
    count_in: int,
    count_out: int,
    passby: int = 0,
    turnback: int = 0,
    avg_stay_time: int = 0,
) -> dict:
    """
    推送客流数据（有人经过时调用）。
    
    参数:
        count_in:    该时段进入人数
        count_out:   该时段离开人数
        passby:      该时段经过人数
        turnback:    该时段折返人数
        avg_stay_time: 平均逗留时间（毫秒）
    
    返回服务器响应字典。
    """
    now_ms = int(time.time() * 1000)  # 当前时间的毫秒时间戳

    payload = {
        "sn": DEVICE_SN,
        "endTime": now_ms,
        "startTime": now_ms - 30000,  # 假设数据区间为最近 30 秒
        "in": count_in,
        "out": count_out,
        "passby": passby,
        "turnback": turnback,
        "avgStayTime": avg_stay_time,
        "time": int(time.time()),
        "reportDate": time.strftime("%Y-%m-%d"),
    }

    try:
        resp = requests.post(DATA_UPLOAD_URL, json=payload, headers=HEADERS, timeout=10)
        result = resp.json()
        if result.get("code") == 0:
            print(f"[✓] 数据推送成功 | in={count_in} out={count_out}")
        else:
            print(f"[✗] 数据推送失败 | code={result.get('code')} msg={result.get('msg')}")
        return result
    except requests.exceptions.RequestException as e:
        print(f"[✗] 数据推送异常 | {e}")
        return {"code": -1, "msg": str(e)}


def query_device_info() -> dict:
    """
    查询设备列表，获取当前设备的 ID 和状态。
    """
    try:
        resp = requests.get(DEVICE_LIST_URL, timeout=10)
        devices = resp.json().get("data", [])
        for dev in devices:
            if dev.get("serialNumber") == DEVICE_SN:
                return dev
        print(f"[!] 设备 sn={DEVICE_SN} 未在系统中注册")
        return {}
    except requests.exceptions.RequestException as e:
        print(f"[✗] 查询设备信息异常 | {e}")
        return {}


# ==================== 主程序 ====================
if __name__ == "__main__":
    print("=" * 50)
    print("客流芸系统 - 设备推送接入示例")
    print(f"服务器:   {SERVER_HOST}:{SERVER_PORT}")
    print(f"设备 SN:  {DEVICE_SN}")
    print("=" * 50)

    # 1. 先查一下设备是否已在系统中注册

    if device:

        print(f"  设备名称:    {device.get('name')}")
        print(f"  在线状态:    {device.get('status')}")
    else:
        print("[!] 请先在系统中添加该设备")

    # 2. 推送一次心跳
    print("\n[2/4] 推送心跳...")
    heartbeat_result = push_heartbeat()

    # 3. 推送一次客流数据（模拟有人进出）

        count_in=3,
```

## 5. 常见问题

### Q1: 推送后一直返回 `code: 1, msg: "device not registered"`？

**原因**：设备 SN 未在客流芸系统中注册。

**解决方案**：
1. 登录客流芸 Web 界面 → **「设备管理」** → **「添加设备」**
2. 确保填入的 `serialNumber` 与设备推送的 `sn` **完全一致**（包括大小写）
3. 保存后再重新推送

**验证**：通过 API 查询设备列表，确认设备已出现：

```bash
curl http://<服务器IP>:15678/api/devices | python -m json.tool
```

---

### Q2: 推送后设备显示 "离线"？

**原因**：心跳超时未收到。系统如果超过约 3 分钟未收到某个设备的心跳，会将其标记为离线。

**解决方案**：
1. 确认设备已上电且正常运行
2. 检查设备推送地址配置是否正确
3. 从设备端 telnet 测试网络连通性：
   ```bash
   # 在设备端或另一台机器上测试
   telnet <服务器IP> 15678
   ```
4. 检查防火墙是否放行了端口 15678

---

### Q3: 如何查看推送日志？

**方式 A：查看系统日志文件**

系统日志位于安装目录下的 `data/fluxavision.log` 文件：

```bash
# Windows 命令行
type D:\FluxAvision\FluxAvision_Kly\data\fluxavision.log | findstr "推送|心跳|设备推送"
```

日志中关键信息示例：

### Q4: 数据推送成功，但在仪表盘上看不到数据？

**原因排查**：

1. **数据归属的日期/小时不对**：
   - 检查推送的 `endTime` 是否正确。系统根据 `endTime`（毫秒时间戳）计算数据归属到哪天的哪个小时
   - 如果 `endTime` 是过去的日期，数据会归到过去的那天

2. **时间戳格式错误**：
   - `endTime` 应为毫秒级时间戳（13 位数字），如 `1716897600000`
   - 如果传了秒级时间戳（10 位数字），系统也能兼容，但请注意时区问题

3. **选错了查询日期**：
   - 仪表盘默认显示今日数据
   - 如果推送的是昨天的数据，需要在历史数据中查看

---

### Q5: 数据校验失败怎么办？

**场景**：推送返回 `code: 1`，但不是 "device not registered" 的报错。

**可能的原因**：

| 报错信息 | 原因 | 解决方案 |
|---------|------|---------|
| `"invalid json"` | 请求体不是合法的 JSON | 检查 JSON 格式（可使用 jsonlint.com 校验） |
| `"sn is required"` | 请求体中缺少 `sn` 字段 | 补充设备 SN |
| `"endTime is required"` | 数据上传时缺少 `endTime` 字段 | 补充 endTime 字段 |

**验证 JSON 格式正确性**：

```bash
# 使用 python 校验 JSON
echo '{"sn": "xxx", "endTime": 1716897600000}' | python -m json.tool

# 如返回格式错误信息，说明 JSON 有问题
```

---

### Q6: 系统支持多少台设备同时推送？

**答**：
- **License 限制**：取决于激活码授权的路数（如 4 路、8 路、16 路）
- **硬件限制**：取决于服务器的 CPU 和网络带宽
- 每台设备每分钟推送 1 次心跳 + 不定次数的数据上传，一般服务器可以轻松支持上百台设备

---

### Q7: 推送的数据会覆盖之前的数据吗？

**答**：**不会覆盖**，新推送的数据会**累加**到已有的记录上。

例如：
- 14:05 推送 `in: 3, out: 2`
- 14:08 推送 `in: 1, out: 1`
- 最终 14 时的记录：`countIn = 3 + 1 = 4`，`countOut = 2 + 1 = 3`

---

### Q8: 时间戳用秒还是毫秒？

**答**：两种格式均支持，系统自动识别：

| 位数 | 精度 | 示例 |
|------|------|------|
| **10 位** | 秒 | `1716897600`（代表 2026-05-28 12:00:00） |
| **13 位** | 毫秒 | `1716897600000`（推荐，精度更高） |

> 建议使用 **13 位毫秒时间戳**，以避免精度丢失。
> 获取当前毫秒时间戳：`python -c "import time; print(int(time.time() * 1000))"`

---

### Q9: 推送地址的端口为什么是 15678？

**答**：15678 是客流芸系统的 **默认 API 端口**。设备推送接口（`/klyun/kl/equipapi/binocular/*`）和其他 API 接口（`/api/*`）都运行在同一个服务上。

> 如果部署时通过环境变量 `API_PORT` 修改了端口，请使用修改后的端口。

---

### Q10: 如何测试推送地址是否可达？

从任何一台能与服务器通信的机器上测试：

```bash
# 测试服务器端口是否开放
telnet <服务器IP> 15678

# 或用 curl 测试心跳接口
curl -X POST http://<服务器IP>:15678/klyun/kl/equipapi/binocular/heartBeat \
  -H "Content-Type: application/json" \
  -d '{"sn": "test-sn-001"}'
```

如果 telnet 连接失败，请检查：
1. 服务器是否在运行
2. 防火墙是否放行了端口
3. 网络路由是否可达
